3. Monitoring data and purpose

3. Данные мониторинга и цель

The planned Threads integration uses authorization by a Threads account holder and keyword searches. The current collector processes post ID, text, public username, publication time and permalink. It uses these fields to find relevant public requests for services, identify duplicate results and allow a person to review the original source. The collector does not request private messages, passwords or private group content.

Планируемая интеграция использует авторизацию владельца аккаунта Threads и поиск по словам. Текущий модуль обработки использует ID публикации, текст, публичное имя, время и ссылку. Эти поля нужны для поиска публичных запросов на услуги, исключения повторов и ручного просмотра источника. Модуль не запрашивает личные сообщения, пароли или содержимое закрытых групп.

4. Processing and recipients

4. Обработка и получатели

Monitoring records are stored in the operator’s database. Where delivery is configured, selected publication text and public source details can be sent to a designated Telegram work group for review. Where AI classification is enabled, publication text is sent to the OpenAI API; the implementation attempts to redact URLs, email addresses, phone numbers and username mentions first. Redaction does not guarantee removal of every personal detail from free text. Meta, Telegram, OpenAI and the hosting platform also process data under their own policies.

Записи мониторинга хранятся в базе оператора. При включённой доставке выбранный текст и публичные сведения об источнике могут отправляться в назначенную рабочую группу Telegram для оценки. При включённой классификации текст передаётся в API OpenAI; перед отправкой реализация пытается удалить URL, email, телефоны и упоминания имён. Такая очистка не гарантирует удаление всех персональных сведений из текста. Meta, Telegram, OpenAI и платформа хостинга также обрабатывают данные по собственным правилам.

5. Retention and control

5. Хранение и управление

The current collector removes its duplicate-detection entries older than 30 days. This is not a 30-day deletion rule for stored publication records or Telegram messages. Publication records remain until removed by the operator or through a deletion request. Copies delivered to recipients may require separate removal. Contact us for details about a particular record and to request access, correction, objection to further processing or deletion.

Текущий модуль удаляет записи для обнаружения повторов старше 30 дней. Это не означает автоматическое удаление самих публикаций или сообщений Telegram через 30 дней. Записи публикаций сохраняются до удаления оператором либо по запросу. Отправленные получателям копии могут требовать отдельного удаления. Свяжитесь с нами для уточнения конкретной записи, запроса доступа, исправления, возражения против дальнейшей обработки или удаления.

6. Authorization and removal

6. Авторизация и удаление

When an authorized integration is activated, access tokens are used by the service to call Meta’s API and are not intended for public display. A connected account holder can revoke the app in the platform’s connected-app settings. Revocation stops further authorized API access; previously stored records need a separate deletion request. See data deletion instructions. Do not email passwords or access tokens.

После активации авторизованной интеграции токены используются сервисом для запросов к API Meta и не предназначены для публичного показа. Владелец подключённого аккаунта может отозвать приложение в настройках подключённых приложений платформы. Отзыв прекращает дальнейший авторизованный доступ; ранее сохранённые записи удаляются по отдельному запросу. См. инструкцию удаления. Не отправляйте пароли и токены по почте.
