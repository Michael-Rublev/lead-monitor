3. Monitoring data and purpose

3. Данные мониторинга и цель

The planned Threads integration uses authorization by a Threads account holder and keyword searches. The current collector processes post ID, text, public username, publication time and permalink. It uses these fields to find relevant public requests for services, identify duplicate results and allow a person to review the original source. The collector does not request private messages, passwords or private group content.

Планируемая интеграция использует авторизацию владельца аккаунта Threads и поиск по словам. Текущий модуль обработки использует ID публикации, текст, публичное имя, время и ссылку. Эти поля нужны для поиска публичных запросов на услуги, исключения повторов и ручного просмотра источника. Модуль не запрашивает личные сообщения, пароли или содержимое закрытых групп.

4. Processing and recipients

4. Обработка и получатели

The first Threads version is an internal tool for NEW SOLUTIONS DOO. It does not send Threads data to Telegram or OpenAI. The application backend is hosted by Contabo in the EU region shown in the customer panel. Contabo GmbH is based in Germany, and its DPA lists Contabo France SAS in France as a data-center subprocessor. These hosting providers process data needed to provide the service. Posts accessed through the connected account’s basic permission are displayed only to that account holder. Any later Telegram integration will require verified provider processing locations and updated data-handling disclosures before activation.

Первая версия Threads — внутренний инструмент NEW SOLUTIONS DOO. Она не передаёт данные Threads в Telegram или OpenAI. Сервер приложения размещён у Contabo в регионе ЕС, указанном в кабинете. Contabo GmbH зарегистрирована в Германии; в её DPA указан субподрядчик дата-центра Contabo France SAS во Франции. Эти провайдеры обрабатывают данные, необходимые для хостинга. Публикации, полученные по базовому разрешению подключённого аккаунта, показываются только его владельцу. Для последующей интеграции с Telegram до её включения потребуется подтвердить страны обработки у провайдера и обновить сведения об обработке данных.

5. Retention and control

5. Хранение и управление

The current working application uses search results within an authenticated session lasting up to eight hours. A new search replaces the previous result list; publication text is not written to a persistent search database. App-owned connection credentials are stored privately until disconnected, revoked or removed through a deletion request. Contact us about a particular record or to request access, correction, objection to further processing or deletion.

Рабочая версия использует результаты поиска в авторизованном сеансе длительностью до восьми часов. Новый поиск заменяет предыдущую выдачу; текст публикаций не записывается в постоянную базу поиска. Данные подключения приложения хранятся отдельно и приватно до отключения, отзыва или удаления по запросу. Свяжитесь с нами для уточнения конкретной записи, запроса доступа, исправления, возражения против дальнейшей обработки или удаления.

A separate private-code demonstration is available to Meta App Review personnel using their own Threads account. A reviewer’s access token remains only in server session memory for up to one hour, and their results are available only in that session. Reviewers cannot access the saved company connection or send Telegram notifications. Exit review session clears their connection and results.

Для сотрудников Meta App Review предусмотрена отдельная демонстрация по приватному коду с подключением их собственного аккаунта Threads. Токен проверяющего хранится только в памяти серверного сеанса до одного часа; результаты доступны только в этом сеансе. Проверяющий не имеет доступа к сохранённому подключению компании и не может отправлять уведомления в Telegram. Выход из режима проверки очищает его подключение и результаты.

6. Authorization and removal

6. Авторизация и удаление

When an authorized integration is activated, access tokens are used by the service to call Meta’s API and are not intended for public display. A connected account holder can revoke the app in the platform’s connected-app settings. Revocation stops further authorized API access; previously stored records need a separate deletion request. See data deletion instructions. Do not email passwords or access tokens.

После активации авторизованной интеграции токены используются сервисом для запросов к API Meta и не предназначены для публичного показа. Владелец подключённого аккаунта может отозвать приложение в настройках подключённых приложений платформы. Отзыв прекращает дальнейший авторизованный доступ; ранее сохранённые записи удаляются по отдельному запросу. См. инструкцию удаления. Не отправляйте пароли и токены по почте.
